# 0.3.7 音频播放检查

## 已修复
- Windows 菜单帧的音频事件未被消费，导致约 40 秒后的三个待机声音完全漏播。两端现共用菜单音频事件分发。
- 原版分析记录 435370 / 435980 显示约 40 秒开始同时播放 _1、_2、_3；435880 释放这些声音。现离开菜单会停止三段声音。
- 两端补接菜单及设置返回的音乐播放／停止命令。主菜单每 165 秒重播的指令现在会真正重启曲目，而不是被“同一曲目已经播放”过滤；本地完整曲目时长为 169.56 秒。
- 打地鼠返回的 cd=0 停止音乐指令补接。
- Windows 按文件停止声音改用持久绑定与声音实例登记，不再依赖会被清理的运行记录；统一大小写、路径分隔符及 WAV/FLAC 别名。

## 素材限制
绑定表中的 92、95、96、97、98、104、105、106、112、116 共十个 WAV 对应文件不在当前 FLAC 资源中，本地原始素材目录也没有找到。不能把这部分漏音归因于 FLAC 解码或直接用其他文件代替。

## 检查范围
核对主机菜单、设置、片头演出、小游戏的音频事件消费，静态扫描关卡音效绑定和文件引用；针对性验证菜单三个声音可解码并提交到设备、停止声音不受记录清理影响、循环音效及停止／重放。
这不是逐关完整试听或原版全音效时序一致性证明。原版分析记录为此前保留的反编译证据，不等同于本轮重新实测原版程序。

## 本轮验证结果
菜单音频分发、退出菜单停止、165 秒重播命令、运行记录清理后的文件停止、异步音效队列、曲目交接、菜单启动检查通过。207 个 FLAC 经应用解码器还原后与原 WAV 的 PCM 数据一致。Switch 编译及 NSP 内容哈希校验通过，尚未完成本版实机试听。
